## Проверки Chromium
60/60 автоматических проверок прошли (полный список и последовательность Tab: `qa/results.json`). Сценарий: пустая форма, неверное расширение, чтение TXT, пример, загрузка, отмена, результат, подсветка, безопасный вывод уточнения, возврат, ошибка и повтор. Проверены 390, 720 и 1440 px: без горизонтального переполнения, в том числе при 1000 строках. Использованы Tab, Enter, Space, Escape через Playwright; подтверждены видимый фокус и переход фокуса к кнопке возврата. Ошибок JS в этой проверке нет.

Ограничение среды: Chromium блокирует переходы file:// и HTTP, поэтому тест использовал реальный собранный HTML со встроенными CSS, JS и локальными JPEG; для каталога проверено наличие пяти iframe, а каждое состояние проверено отдельно. Это не проверка сетевой доставки или загрузки iframe через реальный HTTP. Повторить в обычном браузере после публикации. 720 px — проверка приближённой CSS-ширины при 200% на 1440, не настоящий браузерный зум. Ручной скринридер не проверялся.

## Контраст и семантика
Расчёт по WCAG для непрозрачных пар токенов (требование лекции: 4,5:1 обычный текст, 3:1 крупный текст и элементы): основной/белый 17,74:1; вторичный/серый 6,93:1; вторичный/белый 7,56:1; текст/лайм 13,08:1; успех/белый 7,13:1; предупреждение/белый 6,85:1; ошибка/белый 6,47:1; синий/белый 6,70:1; белый/тёмная шапка 17,06:1. Граница поля теперь 7,56:1 на белом. Это не полный аудит фотографий, прозрачных фонов и всех сочетаний состояний.

Семантика: кнопки действий — button, якорь перехода — a, поля имеют label или aria-label, фотографии — alt, декоративный SVG скрыт, заголовки имеют последовательную иерархию основного сценария, состояния скрываются атрибутом hidden. Кнопки и поля из partials, динамический пункт результата — из template. JS использует textContent вместо вставки пользовательского HTML. Размеры и цветовые значения вынесены в tokens.css; media queries сохраняют брейкпоинты литералами, так как var() в обычных media query не поддерживается.

## Масштабирование 200%

Пользователь подтвердил, что сайт работает при браузерном масштабе 200%. Отдельный скриншот и детальный протокол не предоставлены. Автоматическая проверка при 720 px остаётся дополнительной, а не заменой реального масштабирования.

Для повторения: из папки handoff запустить `python -m http.server 8001 --bind 127.0.0.1`, открыть `http://127.0.0.1:8001/index.html`, F12 → Lighthouse → Accessibility → Desktop/Mobile → Analyze page load. Для масштаба 200% использовать меню Chrome, затем вернуть 100% через Ctrl+0.

## Воспроизводимость
`python build.py`; `python -m pip install playwright`; `python qa/check.py` (указать `CHROMIUM_PATH` к установленному Chromium). Скрипт не делает запросов к ML или hh.ru. Файл results.json — фактические результаты этой проверки.

## Последняя правка оформления
Убрана прямоугольная подложка текста этапов, оставлен градиент фотографии и клавиатурный фокус. Оценки Lighthouse 100/100 получены до этой CSS-правки; требуется повторить Lighthouse Desktop и Mobile после изменения. Проверка зума пользователя также относится к предыдущей версии.
