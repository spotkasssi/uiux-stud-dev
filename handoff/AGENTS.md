# AGENTS.md — Сверка

## Сценарий и стек
Пользователь — соискатель. Он вводит резюме и описание вакансии, запускает сверку, читает совпадения и источники, уточняет только реальный опыт. HTML, CSS, Jinja2 для сборки, минимально необходимый JavaScript без React, Tailwind и сборщиков JS. Дальнейший целевой стек — FastAPI, Jinja2 и HTMX. Не подключать API без отдельной задачи.

## Команды
- `python -m pip install -r requirements.txt`
- `python build.py` — пересобрать `index.html` и `states.html` из шаблонов.
- `python -m http.server 8000 --bind 127.0.0.1` — открыть http://127.0.0.1:8000/.
- `python -m pip install playwright` и `python -m playwright install chromium` для QA. Скрипт `python qa/check.py` использует Chromium из `CHROMIUM_PATH` (по умолчанию `/usr/bin/chromium`); на Windows указать путь к chrome.exe через переменную окружения.

## Правила
- Источник правды: `pages/`, `partials/`, `static/`; сгенерированные `index.html`, `states.html` не редактировать вручную.
- Один компонент — один partial; кнопки и поля через макросы. Состояния `state-empty`, `state-loading`, `state-error`, `state-result`, `state-low-confidence` отдельно. Не дублировать рабочую разметку ради галереи.
- Цвета, размеры шрифтов, отступы, радиусы — через `var()` из `static/css/tokens.css`; не добавлять HEX или новые значения в компоненты. Существующие размеры и брейкпоинты сохранять. Изменять токены только с обоснованием. Не выходить за 15 цветов.
- Работать по DESIGN.md: светло-серый первый экран, четыре фотографии, лаймовый акцент, симметричные колонки. Не добавлять лишние карточки и учебные надписи в интерфейс.
- Кнопка — действие, ссылка — переход; подпись каждого поля, осмысленный alt, видимый фокус. Не использовать inline onclick и не вставлять пользовательский текст через innerHTML.
- Не придумывать опыт, цитаты, результаты модели или источник вакансии. Обозначать демонстрационный режим. API-ключи и персональные данные не коммитить.
- Одно изменение за раз. После каждой правки собрать, открыть на 390 и 1440 px, пройти Tab/Enter/Space/Escape, открыть states.html, проверить 200% зум, сравнить с эталоном в qa/reference. Реальные результаты фиксировать в qa.md. Lighthouse Desktop/Mobile записывать только после запуска.
