# Сверка — пакет передачи (практика 5)

Цель: передать основной сценарий из практики 4 в разработку. Согласованный интерфейс сохранён. Пакет не требует API-ключа и не отправляет данные наружу. Дизайн подготовлен к последующему переносу на FastAPI/Jinja2/HTMX, но серверная интеграция пока не входит в эту сдачу.

## Как открыть
Готовая сборка: открыть `index.html` в Chrome/Edge. Для надёжной проверки ссылок и ресурсов можно запустить локальный сервер из каталога handoff:

```bash
python -m pip install -r requirements.txt
python build.py
python -m http.server 8000 --bind 127.0.0.1
```

Открыть http://127.0.0.1:8000/; все состояния — http://127.0.0.1:8000/states.html. На Windows вместо `python` при необходимости использовать `py`. Для запуска готовых HTML Jinja2 не нужен; он нужен только для повторной сборки. Остановить сервер Ctrl+C.

## Структура и экраны
- `pages/base.html` — общий каркас; `pages/index.html` — сборка сценария. `pages/upload.html` — главная и форма; `pages/result.html` — результат. Это Jinja-фрагменты, не открывать их отдельно в браузере.
- `partials/button.html`, `field.html`, `file-upload.html`, `notification.html`, `result-card.html`, `steps.html`, `experience-editor.html` — переиспользуемые компоненты; header/footer/logo — общий каркас.
- `partials/state-empty.html`, `state-loading.html`, `state-error.html`, `state-result.html`, `state-low-confidence.html` — состояния; загрузка включена в уведомление на форме, низкая уверенность — внутри результата.
- `static/css/tokens.css`, `components.css`; `static/js/app.js`; `static/assets/` — фотографии; `static/icons/` — SVG.
- `states.html` — галерея всех состояний, ссылки на отдельный интерактивный пример. `?state=stress` — 1000 требований, `?fail=1` — имитация ошибки при отправке формы.
- `AGENTS.md`, `DESIGN.md`, `qa.md`, `qa/` — правила, контракт и доказательства проверок.

## Контракт данных
Предварительный, для будущих Pydantic-моделей. Сейчас заполняется браузерным алгоритмом; серверных эндпоинтов нет.

| Поле | Тип | Пример | Источник |
|---|---|---|---|
| cv | string, непустая | Python, FastAPI | поле ввода / TXT |
| file | file или null | resume.txt | файл пользователя, до 5 МБ |
| url | string или null | https://hh.ru/vacancy/139715357 | пользователь, HTTPS |
| job | string, непустая | Python\nDocker | описание вакансии, строка = пункт |
| rows | array[Requirement] | список из 7 пунктов | локальная сверка |
| rows[].name | string | FastAPI | строка описания |
| rows[].status | enum yes/check/no | check | точное/частичное/нет совпадения |
| rows[].quote | string | Python, FastAPI | дословная строка из cv, иначе пусто |
| rows[].note | string | Есть частичное совпадение | пояснение алгоритма |
| fit | integer 0–100 | 79 | round(100 × (yes + 0.5 × check) / total) |
| counts | object: yes/check/no integers | 5/1/1 | подсчёт строк |
| origin | string | описание введено пользователем | метка источника |
| answer | string | проект, роль, результат | уточнение пользователя |
| draft | string | тот же ответ | черновик без генерации фактов |
| state | enum empty/loading/error/result/low-confidence | result | UI |
| progress | integer 0–100 | 50 | демонстрационный таймер |
| error | string или null | сервис анализа не ответил | ошибка сценария |

Нулевой набор не интерпретировать как оценку 0: показывать пустое состояние. Индекс — эвристика, не вероятность или уверенность ML. В будущем `/predict` сможет принимать поля, возвращать `state-result` или `state-error` HTML; HTMX `hx-target` заменит область результата, `hx-indicator` покажет загрузку. Контракт и серверный рендеринг динамических полей должны быть реализованы отдельно. Сейчас результат заполняется безопасно через textContent, а элементы списка создаются из HTML template.

## Ограничения
- Нет подключённой ML-модели, FastAPI, HTMX и автоматического скачивания вакансий. Данные остаются в браузере.
- TXT читается; PDF/DOCX проверяются по расширению и размеру, текст вставляется вручную. Специальная привязка к хешу одного PDF удалена, поскольку она не является настоящим распознаванием. Файлы и персональные сведения из исходного резюме не публикуются. Пример обезличен.
- Ссылка hh.ru сохранена, но оригинальное описание не получено. Пример требований к Python-разработчику помечен как демонстрационный.
- Прогресс имитируется, нет сетевого запроса. Низкая уверенность означает наличие частичных совпадений, не вероятность ML. Частичный результат обработки не предусмотрен.
- Проверки Chromium проведены на встраиваемой сборке (ограничение навигации среды), не на внешнем сервере; Lighthouse на главной странице (Desktop 100/100 по скриншоту, Mobile 100/100 по сообщению и скриншоту участника) и работа при браузерном зуме 200% подтверждены пользователем в локальном Chrome. После удаления прямоугольной подложки текста на фото Lighthouse и зум следует повторить. Отдельный аудит результата и настоящий скринридер не подтверждены; см. qa.md.
