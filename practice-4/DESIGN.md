# Сверка — дизайн-система

Практика 4 · Разработка интерфейсов

## 1. Идея
Сверка помогает студенту и выпускнику сопоставить резюме с требованиями вакансии. Характер: точный, контрастный, честный. Сохраняем из практики 3 светло-серый полноэкранный вводный блок, светлые рабочие экраны, знак логотипа и яркий зелёный акцент. Рабочий сценарий: резюме → вакансия → сверка → проверка цитат → уточнение опыта.

## 2. Чего не делаем
Не показываем выдуманный процент соответствия или вероятность найма. Не выдаём пустой результат за успешный анализ. Не полагаемся только на цвет; статус всегда подписан. Не добавляем декоративные градиенты, эмодзи, карточки в рабочем сценарии и произвольные значения цветов, отступов, радиусов или текста. Не выдаём демонстрационный анализ за ML.

## 4. Типографика
Inter, затем Arial / sans-serif. 5 стилей: display 64 (адаптивный), title 28, lead 20, body 15, meta 13. Межстрочные интервалы: 1.06 / 1.2 / 1.55 / 1.45. Заголовки 700–800, поля 600, обычный текст 400. Длинный текст переносится, цитаты не обрезаются.

## 5. Форма и сетка
Отступы `--s-1` … `--s-8`: 4, 8, 12, 16, 24, 32, 48, 64 px. Радиусы `--r-sm/md/lg`: 4, 8, 12 px; ссылки на шкалу отступов. Толщина границы 1 px, фокус 2 px. Размеры контейнеров и точек перелома в rem; ширина по сетке в долях. Две колонки на широком экране, одна при ширине до 42rem. Отступы внутри компонентов только из шкалы.

## 6. Компоненты
| Компонент | Класс | Варианты и состояния |
|---|---|---|
| Кнопка | btn, primary | Основная, вторичная; normal, hover, active, focus-visible, disabled, loading (блокирует повтор) |
| Поле ввода | field, control | Обычное, hover, focus, ошибка, disabled; подпись сверху, ошибка снизу |
| Зона выбора файла | drop | Пусто, drag-over, выбран, неверный формат/размер, удаление; TXT читается локально; исходный PDF-пример сопоставляется по SHA-256, прочие PDF/DOCX требуют вставки текста; загрузки на сервер нет |
| Индикатор | progress, skeleton | 0–100, текст этапа, спиннер справа снизу на форме; при завершении сменяется уведомлением |
| Уведомление | notice | Информация, успех, предупреждение, ошибка; конкретный текст и следующий шаг |
| Требование | requirement | Есть, Проверьте, Нет; normal, hover, focus-visible, выбранное; цитата и пояснение |

Компоненты повторно используются в `index.html` и `components.html`. Состояния на уровне страницы: empty, loading, error, result. Неуверенность — дополнительный вариант результата. У каждого требования источник или явное отсутствие цитаты; при пробеле доступен вопрос и черновик из ответа пользователя.

### Движение и обратная связь
Длительность перехода 220 мс, нажатия 140 мс, цикл индикатора 900 мс; общая кривая `--ease-interactive`. При наведении кнопка приподнимается на толщину фокуса и получает тень из токенов. При нажатии сжимается до 97%, при фокусе видна контрастная рамка. В состоянии загрузки обе разновидности кнопки блокируются, показывают текст и вращающийся спиннер. Недоступная кнопка не смещается. Скелетон плавно меняет прозрачность. При `prefers-reduced-motion: reduce` отключаем переходы, смещения и вращение; текст и цвет сохраняют обратную связь. В UI kit зафиксированы 12 образцов, отдельно — две интерактивные кнопки.

## 7. Тексты
Обращение на «ты» (из brief.md), коротко и предметно. Ошибка отвечает на три вопроса: что произошло, что с данными, что дальше. Поля не валидируем до взаимодействия; обязательные проверяем при отправке, фокусируем первое проблемное поле. При исправлении скрываем ошибку. При отсутствии данных не показываем ноль подтверждений. В результатах счёт по статусам, не оценка качества резюме.

## 8. Правило для дальнейшей разработки
Работай по DESIGN.md, не используй значений, которых нет в tokens.css. Для нового компонента сначала переиспользуй смысловой токен и существующий класс; при необходимости обоснуй новый токен. Не добавляй новые HEX в styles.css или HTML. Проверь пустой экран, ожидание, сбой, длинные строки и мобильную ширину.

### Композиция рабочей страницы
Поля пусты, образцы серым placeholder. Подтверждение формата и текста — зелёной подписью; ошибки — красным текстом рядом с источником ошибки. Во время сверки форма остаётся видимой и блокируется, индикатор фиксирован справа снизу. На его месте показывается уведомление об успехе или сбое. Результат использует единый счёт и полосу совпадений, две колонки со строками и цитатами, без декоративных карточек.

## Обновление главной и сценария
Сохранён светло-серый фон. Четыре локальные сгенерированные фотографии (повар, строитель, разработчик, медработник) размещены в `assets/`. На широком экране при наведении или клавиатурном фокусе этап расширяется, остальные сужаются; высота не меняется. На узком экране текст виден сразу. Скриншот 17 — наведение. Фотографии не добавляют новых CSS-цветов.
Отдельное поле требований и дублирующий предпросмотр объединены в единственный блок описания выбранной вакансии. Пример резюме основан на первой странице предоставленного `resume-python-developer.pdf`, без шаблонных полей и служебной страницы. Ссылка на вакансию №139715357 сохранена, её содержание недоступно. Семь учебных пунктов для Python-разработчика не являются подтверждёнными требованиями этой вакансии; результат явно маркируется демонстрационным. Для реальной сверки вставь описание вакансии вместо примера. Заранее извлечённый текст может подставляться для точного исходного PDF по SHA-256 при наличии Web Crypto; эта ветвь не проверена в браузерной среде. Универсального PDF-парсера нет. Автотесты выполняют рендеринг с встраиванием CSS, JS и локальных изображений из-за блокировки file:// в тестовой среде.

## Выравнивание формы
На широком экране обе колонки используют общие строки CSS subgrid: заголовки, зоны загрузки и ссылки, текстовые поля. Высота текстовых полей одинаковая при первом открытии; на узком экране колонки складываются вертикально. Размер lead увеличен до 20, заголовок первого экрана крупнее. Учебные подписи и ссылки на тестовые состояния убраны из публичного интерфейса; каталог компонентов и тестовые URL сохранены для сдачи. Ограничения текстового сопоставления и пометка непроверенного примера вакансии сохранены.
